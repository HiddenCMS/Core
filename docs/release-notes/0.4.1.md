# HiddenCMS 0.4.1

Cette version corrige la mise a jour depuis `0.3.4` lorsqu'un theme ou un
module HiddenCMS est installe par Composer.

## Corrections

- Les dependances `hiddencms/*` ajoutees par l'administrateur sont preservees
  lorsque le manifeste Composer du core est remplace.
- Le lock Composer des addons HiddenCMS est actualise pendant le changement de
  version du core, afin de recuperer leurs contraintes de compatibilite a jour.
- Horizon et News acceptent desormais les cores `0.3.x` et `0.4.x`.
- Le cache de statut est supprime apres une mise a jour reussie : la nouvelle
  version est affichee immediatement dans l'administration.

## Diagnostic et retour arriere

- Chaque etape de la mise a jour est identifiee dans les messages d'erreur.
- Le dernier echec est conserve dans `cache/updates/last-error.json` et affiche
  sur la page Mises a jour.
- Un journal durable est ecrit dans `logs/core-updater.log`.
- Les metadonnees de sauvegarde indiquent la cause du retour automatique et un
  eventuel echec de restauration.

Version du schema : `0.3.6` (inchangee). Mise a jour directe possible depuis
`0.3.4` et `0.4.0`.

## Installation encore en 0.3.4 apres un retour automatique

L'ancien updater est charge avant que les fichiers de la nouvelle release ne
soient copies. Pour une installation ayant deja rencontre le conflit Composer
de `0.4.0`, remplacer une seule fois les fichiers suivants par ceux de `0.4.1`
avant de relancer la mise a jour depuis l'administration :

- `hiddencms/libraries/core_updater.php` ;
- `hiddencms/libraries/addon_packages.php`.

Cette amorce preserve les declarations de News et Horizon, actualise leur lock,
puis poursuit normalement la mise a jour du core. Les mises a jour suivantes
utiliseront directement le nouveau mecanisme.
